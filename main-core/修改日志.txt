一、原始程序分析
--------------------------------------------------------------------------------
  原始程序功能:
    1. 使用 QMqttClient 连接 MQTT Broker (192.168.79.1:1883)，订阅 "test/topic"
    2. 使用 readingDataThread 通过串口 /dev/ttyS0 读取传感器数据
    3. simulateDataUpdate() 自行生成模拟温度/湿度数据
    4. 温度 + 湿度两张实时曲线图表 (QLineSeries)
    5. 表格模式可切换查看数据 (10 行保留)
    6. 底部按钮栏: 报警阈值、导出数据(空)、刷新(空)、设置(空)

  原始程序缺陷:
    a. mqttClient 在 MainWindow 构造函数中作为局部变量创建，构造后立即销毁，
       导致 MQTT 连接建立后立刻断开
    b. simulateDataUpdate() 使用随机数据模拟，未使用真实传感器数据
    c. readingDataThread 使用串口而非共享内存，无法与副核通信
    d. on_btnExport_clicked() 为空实现，无法导出数据
    e. 无数据持久化机制
    f. 无光照数据显示


二、新增文件清单（5 个文件）
--------------------------------------------------------------------------------

  [1] sensordata.h
  ------------------------------------------------------------------
  路径: QT_MQTT_UI/sensordata.h
  用途: 定义 SensorData 结构体，与副核 handleJson.h 中的 SenserData
        保持字节级兼容（使用 #pragma pack(push, 1)）
  结构体布局:
    struct SensorData {
        char deviceId[64];     // 设备 ID（64 字节）
        double temperature;    // 温度（8 字节）
        double humidity;       // 湿度（8 字节）
        int light;             // 光照（4 字节）
        char status[16];       // 状态字符串（16 字节）
        long timestamp;        // 时间戳（8 字节，ARM64）
    };  // 总计 108 字节（pack(1) 无对齐填充）


  [2] shmcommunicator.h / shmcommunicator.cpp
  ------------------------------------------------------------------
  路径: QT_MQTT_UI/shmcommunicator.h, shmcommunicator.cpp
  用途: 封装与副核共享内存通信的完整逻辑

  RingBuffer 结构体（与副核 ringBuf.h 完全一致）:
    struct RingBuffer {
        volatile uint32_t write_ptr;   // 写指针（生产者更新）
        volatile uint32_t read_ptr;    // 读指针（消费者更新）
        uint8_t data[DATA_AREA_SIZE];  // 数据区 (8184 字节)
    };

  共享内存布局:
    物理基址:     0xb1004000
    映射大小:     16KB (0x4000)
    A→B 通道:     offset 0x0000 (副核写 → 主核读)
    B→A 通道:     offset 0x2000 (主核写 → 副核读)
    单通道大小:   8KB (0x2000)
    数据区大小:   8184 字节 (8KB - 8字节头部)

  主要方法:
    init()              - 打开 /dev/mem 并 mmap 共享内存
    sendToSecondary()   - 将数据写入 B→A 通道（主核→副核）
    recvFromSecondary() - 从 A→B 通道读取数据（副核→主核）
    statusInfo()        - 返回通信状态详情字符串

  通信协议（与副核 commMsg.c 一致）:
    消息格式: 2 字节小端长度头 + N 字节数据体
    写入流程: 写入长度头 → 写入数据 → __sync_synchronize() → 更新写指针
    读取流程: 读取长度头 → 读取数据 → __sync_synchronize() → 更新读指针
    空判断:   write_ptr == read_ptr
    满判断:   (write_ptr + 1) % DATA_AREA_SIZE == read_ptr
    最大载荷: DATA_AREA_SIZE - 3 = 8181 字节


  [3] databasemanager.h / databasemanager.cpp
  ------------------------------------------------------------------
  路径: QT_MQTT_UI/databasemanager.h, databasemanager.cpp
  用途: SQLite 数据库管理，实现数据持久化

  数据库表结构:
    CREATE TABLE IF NOT EXISTS sensor_readings (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        device_id TEXT NOT NULL,
        timestamp INTEGER NOT NULL,
        temperature REAL,
        humidity REAL,
        light INTEGER,
        status TEXT
    )

  主要方法:
    init(dbPath)      - 初始化 SQLite 数据库（默认路径 ~/.local/share/...）
    insertRecord()    - 插入一条传感器记录
    exportToCsv()     - 导出全部数据为 CSV 文件（含 BOM 头，兼容 Excel）
    recordCount()     - 查询当前记录总数

七、关键设计说明
--------------------------------------------------------------------------------

  1. 结构体兼容性:
     Qt 侧 SensorData (sensordata.h) 使用 #pragma pack(push, 1)
     与副核 SenserData (handleJson.h) 使用 #pragma pack(1) 效果一致
     总大小 = 64 + 8 + 8 + 4 + 16 + 8 = 108 字节 (ARM64, long=8)

  2. 环形缓冲区协议一致性:
     Qt 侧 shmcommunicator.cpp 与副核 commMsg.c 使用完全相同的:
     - 数据结构 (RingBuffer)
     - 消息格式 (2字节小端长度头 + 数据体)
     - 空/满判断逻辑
     - __sync_synchronize() 内存屏障
     - 最大载荷限制 (DATA_AREA_SIZE - 3)

  3. 通道方向:
     Qt 视角:
       B→A 通道 (offset 0x2000) = 发送通道 (Qt 写入 JSON)
       A→B 通道 (offset 0x0000) = 接收通道 (Qt 读取解析后结构体)
     副核视角:
       B→A 通道 (offset 0x2000) = 接收通道 (副核读取 JSON)  ← rx_rb
       A→B 通道 (offset 0x0000) = 发送通道 (副核写入结构体)  ← tx_rb
     命名从副核角度出发 (A=副核, B=主核)，Qt 侧做镜像操作

  4. 线程安全:
     readingDataThread 在独立 QThread 中运行
     使用 exec() 事件循环 + QTimer 定时轮询
     通过 Qt 信号/槽跨线程传递数据 (dataReady 信号)
     ShmCommunicator 方法从单一线程调用，无需额外加锁

  5. 数据库路径:
     Linux: ~/.local/share/QT_MQTT_UI/sensor_data.db
     目录自动创建，支持自定义路径传入

九、与副核程序的协作流程
--------------------------------------------------------------------------------

  1. 主核 Qt 启动 → 初始化共享内存 (/dev/mem mmap)
  2. 副核程序启动 → 初始化共享内存 (/dev/mem mmap)
  3. MQTT Broker 发布 JSON 传感器数据到 test/topic
  4. 主核 mqttClient 收到 JSON → 写入 B→A 通道
  5. 副核 recv_from_root() 读取 JSON → analysisSensorDataJson() 解析
  6. 副核 send_to_root() 将 SenserData 写入 A→B 通道
  7. 主核 readingDataThread 轮询发现新数据 → recvFromSecondary()
  8. 主核 onSensorDataReady() 更新 UI + 写入 SQLite
