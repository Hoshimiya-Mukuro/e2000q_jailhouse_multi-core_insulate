  日期: 2026-04-29

一、程序功能
--------------------------------------------------------------------------------

  [1] MQTT 数据接收
  ------------------------------------------------------------------
  连接 MQTT Broker (192.168.79.1:1883)，订阅 test/topic 主题，
  接收 JSON 格式传感器数据，通过信号转发给主窗口。


  [2] 共享内存跨核通信
  ------------------------------------------------------------------
  通过 /dev/mem 将物理地址 0xb1004000 处的 16KB 共享内存映射到用户空间，
  使用环形缓冲区协议（2 字节长度头 + 数据体，__sync_synchronize 内存屏障）
  与副核进行无锁数据交换：

  - B→A 通道（主核写，副核读）：将 MQTT 收到的 JSON 字符串写入，供副核解析
  - A→B 通道（副核写，主核读）：读取副核解析完成的 SensorData 结构体
    （108 字节，pack(1)，含 deviceId/temperature/humidity/light/status/timestamp）

  readingDataThread 子线程以 500ms 间隔轮询 A→B 通道，有新数据即发射
  dataReady 信号给 UI 线程。


  [3] 实时数据可视化（3 页切换）
  ------------------------------------------------------------------
  页面          内容
  ──────────────────────────────────────────────────
  图表模式      温度曲线（Y 轴自适应）+ 湿度曲线（Y 轴自适应），
               并排显示，各带数值标签和状态标签

  表格模式      6 列数据表（时间/温度/湿度/光照/设备ID/状态），
               最近 10 条记录

  光照图表      独立光照曲线（0-1200 lux），含数值和状态标签

  所有图表保留最近 20 个数据点，超出后自动滚动 X 轴。


  [4] 异常检测与状态指示
  ------------------------------------------------------------------
  每个传感器指标都有阈值判断：
  - 温度: >30°C 或 <15°C → "⚠️ 异常"（红色），否则 "正常"（绿色）
  - 湿度: >80%RH 或 <30%RH → "⚠️ 异常"（红色），否则 "正常"（绿色）
  - 光照: >1000lux 或 <100lux → "⚠️ 异常"（红色），否则 "正常"（绿色）


  [5] SQLite 数据持久化
  ------------------------------------------------------------------
  每条解析完成的传感器记录自动写入 sensor_readings 表：
    id, device_id, timestamp, temperature, humidity, light, status

  数据库存储于: ~/.local/share/QT_MQTT_UI/sensor_data.db
  目录自动创建，支持自定义路径传入。


  [6] CSV 导出
  ------------------------------------------------------------------
  点击 "💾 导出数据" 按钮弹出保存对话框，导出全部记录为 UTF-8 BOM CSV 文件，
  兼容 Excel 直接打开。默认文件名: yyyy-MM-dd_hh-mm-ss_sensor_data.csv


  [7] 设备状态诊断
  ------------------------------------------------------------------
  点击 "📡 设备状态" 按钮弹出对话框，显示:
  - MQTT 客户端连接状态
  - 共享内存各通道可读/可用字节数
  - 数据库记录总数
  - 读取线程运行状态


二、性能分析
--------------------------------------------------------------------------------

  [1] 延迟
  ------------------------------------------------------------------
  环节                          延迟
  ────────────────────────────────────────────
  MQTT 消息到达 → 写入共享内存    < 1ms（sendToSecondary 纯内存操作，无锁）
  读取线程轮询间隔                500ms（定时器触发）
  共享内存读取 → UI 更新          < 1ms（memcpy 108 字节 + Qt 信号跨线程投递）
  ────────────────────────────────────────────
  端到端（MQTT 到 UI）            ≤ 500ms（瓶颈在读线程轮询间隔）

  若需更低延迟，轮询间隔可降至 100ms 甚至 50ms，CPU 开销依然可忽略。


  [2] 吞吐量
  ------------------------------------------------------------------
  - 单条消息最大 8181 字节（环形缓冲区限制）
  - JSON 典型大小约 200-500 字节，即缓冲区可积压约 15-40 条消息
  - 副核处理速度如能跟上 500ms 轮询周期，吞吐约 2 msg/s
  - 缩短轮询间隔可线性提升吞吐


  [3] 内存占用
  ------------------------------------------------------------------
  组件                          内存
  ────────────────────────────────────────────
  共享内存映射                   16KB（虚拟地址空间，非物理分配）
  JSON 接收缓冲区                4KB（副核侧堆分配）
  SensorData 接收缓冲            256 字节（栈分配）
  SQLite 缓存                    取决于 Qt SQL 驱动默认配置，约几十 KB
  图表数据（3 线 × 20 点）       约 2KB
  ────────────────────────────────────────────
  估计总 RSS 增量                < 200KB（不含 Qt 框架自身）


  [4] CPU 占用
  ------------------------------------------------------------------
  - 主线程：空闲（timer 每秒触发一次 updateTime，纯字符串格式化）
  - 读取线程：每 500ms 执行一次 recvFromSecondary
    （读取指针 → 比较 → 可能 memcpy 108 字节），开销可忽略
  - 有数据到达时：cJSON 解析由副核承担，主核仅做 UI 刷新和 SQLite INSERT
  - 稳态 CPU 占用：接近 0%


  [5] 并发安全性
  ------------------------------------------------------------------
  - 共享内存：单生产者单消费者，各核只写自己的通道，无需锁
  - Qt 跨线程：dataReady 信号/槽自动将数据从工作线程投递到主线程
    （Qt 内部使用 queued connection）
  - SQLite：所有写入从主线程调用，无并发问题


三、数据流全景
--------------------------------------------------------------------------------

  ┌─────────────────────────────────────────────────────────┐
  │                     MQTT Broker                          │
  │                 (192.168.79.1:1883)                      │
  │              发布 JSON 到 test/topic                      │
  └──────────────────────┬──────────────────────────────────┘
                         │
  ┌──────────────────────▼──────────────────────────────────┐
  │              主核 Qt 程序 (QT_MQTT_UI)                     │
  │                                                           │
  │  1. mqttClient 收到 JSON                                  │
  │  2. 写入 B→A 通道 (共享内存 offset 0x2000)                │
  │  3. readingDataThread 500ms 轮询 A→B 通道                 │
  │  4. 读取 SensorData 结构体 (108 字节)                     │
  │  5. 更新图表/表格/SQLite                                  │
  └──────────────────────┬──────────────────────────────────┘
                         │ 共享内存 @ 0xb1004000
                         │ ┌──────────────┐
                         │ │ A→B 通道     │ ← 主核读取
                         │ │ (副核→主核)   │
                         │ ├──────────────┤
                         │ │ B→A 通道     │ → 主核写入
                         │ │ (主核→副核)   │
                         │ └──────────────┘
                         │
  ┌──────────────────────▼──────────────────────────────────┐
  │              副核 Buildroot 程序 (JsonMsgHandleCell)       │
  │                                                           │
  │  recv_from_root() → 读取 JSON → analysisSensorDataJson() │
  │  → send_to_root() → 写入 SensorData 结构体               │
  └─────────────────────────────────────────────────────────┘


四、一句话总结
--------------------------------------------------------------------------------

  这是一个低延迟、近零 CPU 开销的跨核数据管道：
  MQTT JSON 进 → 实时图表 + SQLite 持久化出，
  中间由副核承担 JSON 解析负载，主核 UI 始终保持响应。
  500ms 轮询是当前唯一的延迟瓶颈，可按需调低。
